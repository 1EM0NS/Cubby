# ADR-0001：不把浮层窗口挂载到 WorkerW

- 状态：已接受
- 日期：2026-09-19
- 对应原则：P3

## 背景

动态壁纸软件（Wallpaper Engine 等）通过给 `Progman` 发送未公开消息 `0x052C`，让 Explorer 派生出一个 `WorkerW` 窗口，再把播放窗口 `SetParent` 到该层，从而位于"背景层与图标层之间"。桌面整理类工具若想把内容画在图标之下，通常也会走同一条路。

## 决策

Cubby 不调用 `SetParent` 把浮层挂载到 `WorkerW`。浮层保持为**独立顶层窗口**，通过事件驱动的置底来维持 Z 序。

## 理由

1. `SetParent` 之后窗口的鼠标事件经常失效，与我们"盒子区域必须可靠接收点击"的目标（P2）直接冲突。
2. 与壁纸软件争抢 `Progman` / `WorkerW` 下的 Z 序与父子关系，正是腾讯桌面整理导致动态壁纸在静态与动态之间来回闪烁的原因（有副屏时尤其明显）。
3. `0x052C` 是未公开消息，Win11 24H2 的层级行为已经变化，依赖它会让实现非常脆弱。

## 后果

- 需要自行处理置底与 `Win+D` 后的恢复显示（见技术方案 2.3）。
- 无法靠 `SetParent` 自动"永不遮挡应用窗口"，置底逻辑必须可靠并有回归用例（A4）。
- CI 设计原则守卫会拦截 `SetParent`；确需突破时，必须先修改本 ADR 再动代码。
