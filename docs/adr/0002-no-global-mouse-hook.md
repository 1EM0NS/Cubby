# ADR-0002：不注册全局鼠标钩子

- 状态：已接受
- 日期：2026-09-19
- 对应原则：P1

## 背景

Wallpaper Engine 的互动壁纸依赖 `WH_MOUSE_LL` 全局鼠标钩子拦截并转发点击。桌面整理类软件同样需要感知桌面上的双击与拖拽，常见做法是安装自己的全局钩子——一旦钩子函数返回非零值把消息吞掉，钩子链后面的软件就再也收不到点击。这就是"开启桌面整理后互动壁纸点不动"的直接原因。

## 决策

Cubby **不注册任何全局鼠标钩子**。全部交互通过自有的分层窗口接收：鼠标落在盒子区域由我们处理，落在区域外由系统直接派发给下层窗口。

## 理由

1. 钩子链是排他的，任何吞消息行为都会连带影响第三方软件，而且很难在自测中发现。
2. 我们需要的交互能力（点击、双击、右键、拖拽）在自有窗口上都能通过标准窗口消息和 OLE 拖放获得，不需要钩子。
3. 无钩子意味着可以对用户承诺"盒子外的点击行为与未安装本程序时完全一致"。

## 后果

- "双击空白桌面隐藏图标"无法用钩子实现，改为托盘菜单 / 全局热键 / 盒子按钮三种入口（见技术方案第 12 章）。
- 无法感知桌面图标层上的点击事件，只读吸附只能依赖 `LVM_*` 主动读取而非事件通知。
- 若未来确需钩子（例如必须感知桌面空白区的双击），钩子函数中必须无条件 `CallNextHookEx` 放行，并补新 ADR 与专项回归用例（A1 / A3）。
