## 2026-09-19 · 会话 2：代理修复、留痕机制落地、流程首次全闭环

**参与者**：1EM0NS（人）、Trae（AI 助手）

**目标**：解决代理导致的推送失败；建立防止"上下文中断后失忆"的记录机制

### 完成的工作

1. **代理修复**
   - 现象：`git push` 报 `Failed to connect to 127.0.0.1 port 7890`
   - 诊断：全局 `~/.gitconfig` 的 `http.proxy` / `https.proxy` 指向 7890，但该端口**未监听**；本机实际监听的是 **38144**，且端口是动态的，硬编码必然再次失效
   - 处理：在本仓库 `.git/config` 写入**空的** `[http] proxy =` 与 `[https] proxy =` 以覆盖全局，其他仓库行为不变
2. **三层留痕机制**
   - `docs/工作日志.md`：追加式会话记录，最新条目在最上，禁止修改历史条目
   - `AGENTS.md`：P1–P4 红线、工作规矩、环境坑、常用命令
   - `技术方案.md` 13.7：把留痕机制写进流程，而非临时约定
3. **首次走通完整闭环**：issue #17 → 分支 `docs/worklog-and-handover` → PR #18 → CI → squash 合并

### 验证与证据

| 项 | 证据 |
|---|---|
| 代理置空生效 | `git config --get http.proxy` 返回空；`git push` **未加任何 `-c http.proxy=` 绕过参数**即成功 |
| PR 的 CI | `gh pr checks 18 --watch` → `build-and-test` **pass，42s** |
| 合并结果 | `gh pr view 18 --json state,mergedAt` → state=**MERGED**，mergedAt=2026-09-19T08:55:59Z，mergeCommit=`483d66f` |

| 分支保护实际生效 | 本地无法直推 main，必须走 PR；本次正是被迫走 PR 才完成的 |

### 新增环境坑

- `gh pr merge --squash --delete-branch` 合并后**没有把本地仓库切回 `main`**，本地仍停留在已被删除的分支上，随后 `git pull` 报 `no such ref was fetched`，一度误判为合并失败。
  → 判断合并结果必须以 `gh pr view` 的 state 为准；收尾需手动 `git switch main && git pull && git branch -D <分支>`。已写入 `AGENTS.md`。
- 分支保护启用后，**任何文档改动也必须走 PR**，包括工作日志本身。这会让"给日志补一条"也变成一次完整的 PR 流程——属于预期代价，不是缺陷。

## 2026-09-19 · 会话 1：立项、技术方案与开发流程搭建

**参与者**：1EM0NS（人）、Trae（AI 助手）

**目标**：确定桌面整理助手的技术方案，并建立一个能长期做版本迭代的仓库与工作流

### 调研结论

- 腾讯桌面整理「开整理后动态壁纸点不动」的根因**不是资源占用，而是输入抢占**：它铺透明分层窗口并拦截鼠标消息，与 Wallpaper Engine 依赖的全局鼠标钩子（`WH_MOUSE_LL`）争抢输入。官方只能提供"兼容第三方壁纸"开关，并承认交互型壁纸不支持。
- 可借鉴的开源方案：DeskBox（文件不移动、只做映射浮层）、Lively Wallpaper（WorkerW + `SetParent` 塞进壁纸层）、DesktopOK（`LVM_*` 读写图标位置）、Rainmeter（桌面小组件 Z 序）、Seelen UI。
- 技术结论：`WM_NCHITTEST → HTTRANSPARENT` **跨进程无效**（消息被丢弃而非转发），不能用来实现穿透。

### 决策

- 技术栈 .NET 8 + WPF，进程固定 x64（与 Explorer 同位宽才能做 `LVM_*` 通信）
- 四条硬约束 P1–P4（见 `技术方案.md` 1.2），并落成 CI 门禁
- 仓库名 **Cubby**（Public），trunk-based + PR，SemVer 与里程碑绑定
- 「双击空白桌面隐藏图标」默认不做（与 P1 冲突），改为托盘菜单 / 热键 / 盒子按钮
- 不把窗口 `SetParent` 到 WorkerW（ADR-0001）；不注册全局鼠标钩子（ADR-0002）

### 踩过的坑（都是可复现的环境问题）

1. **全局 git 代理失效**：`~/.gitconfig` 里 `http.proxy = 127.0.0.1:7890` 指向未监听的端口，而实际代理端口是动态的（本次为 38144）。已在**本仓库** `.git/config` 把 `http/https.proxy` 置空以覆盖全局，不影响其他仓库。
2. **PowerShell 5.1 会丢弃空字符串参数**：`git config --local http.proxy ""` 实际上没有写入，而 `git config --get` 返回空会**造成"已生效"的假象**。正确做法是直接编辑 `.git/config`，或用 `git -c key=value` 形式。
3. **PowerShell 参数模式不做成员访问**：`gh api -f title=$m.Title` 会把字面量 `System.Collections.Hashtable.Title` 当标题提交（曾产生一个垃圾里程碑，已删除）；描述里的 ASCII 双引号还会破坏原生参数解析。
   → **结论：给 `gh` 传中文内容一律用 `--body-file` 传文件。**
4. **PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 ANSI 解析**，中文报语法错误。`guard.ps1` 已加 BOM。
5. GitHub 不允许 approve 自己的 PR，所以分支保护的强制审批人数必须为 **0**，否则单人项目会把自己彻底锁死。
