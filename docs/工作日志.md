## 2026-09-19 · 会话 17：M2 自动归类规则 DSL（issue #14）

**目标**：按扩展名 / MIME / 时间 / 来源路径 / 正则把新文件归入对应盒子，**不移动文件实体**

### 完成的工作

1. **Core `Rules`**
   - `RuleModel`：条件字段刻意做"平"（不搞多态子类）——这是给用户手写 JSON 用的，
     平结构一眼看懂，版本迁移也简单；取反用 `Negate` 一个开关覆盖"不是这些扩展名"这类需求
   - `RuleEngine`：纯托管、无 IO；**只产出"谁归到哪个盒子"的计划**，
     预览与应用共用同一份计算，不会出现"预览说 A、实际进 B"
   - `MimeTypes`：内置扩展名→MIME 对照表（认不出的落 `application/octet-stream`），
     支持 `image/*` 这类通配
   - `RuleStore`：规则文件读写，原子写 + 坏文件降级 + 版本过高拒绝；首次使用落一份**带示例规则的模板**
2. **App**
   - `RuleService`：算计划 → 只改布局里的 `Items` 引用 → 记下撤销快照；撤销就是把快照恢复回去
   - `RulesWindow`：规则明细 / 预览 / 应用 / 撤销 / 重新加载 / 打开文件；
     **规则不在界面里编辑**（它是 JSON，用任意编辑器改完点重载即可）——换来可导入导出、可版本管理
   - 托盘菜单加「归类规则…」；诊断面板与 `--dump-state` 加规则状态

### 验证与证据

| 项 | 结果 |
|---|---|
| 规则自动化验收 | **PASS**，11 步全过，报告见 `artifacts/rules-report.md` |
| **五类条件各自命中** | PASS：`Screenshot_2026.png`→正则、`photo.jpg`→MIME+扩展名、`notes.md`→时间（最近 1 天）、`old.txt`→时间取反（30 天前）、`app.log`→来源路径 |
| 优先级 | PASS：截图同时符合图片规则，仍由优先级更高的正则规则收走 |
| 目标盒子不存在 | PASS：不硬塞，单独列入「缺失目标」并在界面提示 |
| 预览安全 | PASS：预览后条目数与磁盘指纹都没变 |
| 应用 | PASS：5 条命中全部登记进目标盒子（0 → 5） |
| 一键撤销 | PASS：回到 0 条，且**磁盘指纹始终一致**（P4） |
| 单元测试 | **109/109**（新增 27 个：五类条件 + AND + 取反 + 通配 + 坏正则 + 优先级 + 缺目标 + 规则文件读写） |
| 全部验收回归 | 13 条命令全部 exit **0** |
| 设计原则守卫 | 通过 |

用户自己的 `rules.json` 在验收后被确认**没有被创建**（首次使用才落盘），桌面与布局也没有残留。

### 踩坑

- **空条件的 `All()` 恒为真**：一条"没写条件"的规则会吞掉**所有**条目。
  这个 bug 被单测当场抓住，修法是 `Matches` 里显式要求"已启用 + 至少一个条件"。
  规则引擎里这种"默认真"的语义最容易出事，值得后人警惕。
- 验收一开始直接驱动界面的「应用到桌面条目」按钮，结果它按设计取的是**桌面**候选，
  把用户桌面上匹配的文件真的加进了盒子（随后被撤销）。修法是给窗口开一个候选来源的注入点：
  验收注入自己的临时目录，既覆盖了界面路径，又完全不碰用户的桌面。

### 未完成（诚实说明）

- **MIME 用的是内置对照表**，不是注册表查询或内容嗅探：认不出的扩展名一律二进制类型。
  要更准可以后续加"内容嗅探"作为可选步骤，规则模型不用改
- 归类只作用于**桌面目录里尚未入盒**的条目；不做"新文件一出现就自动归类"的常驻监听
  （那需要一个覆盖多个目录的监视器，留给后续）
- 规则界面不做编辑器（改 JSON + 重载）

### 下一步

issue #12：隐藏 / 显示真实桌面图标（三个入口 + 崩溃恢复，M2 里风险最高的一项）。

## 2026-09-19 · 会话 16：M2 盒子内即时搜索（issue #13）

**目标**：盒子条目变多后能快速定位，不依赖系统索引

### 完成的工作

1. **Core** `BoxSearchIndex`：内存索引（预计算小写名/路径）+ 命中分档
   （展示名前缀 &gt; 展示名包含 &gt; 路径包含），空查询返回全部
2. **App** `SearchService`：每个盒子一份索引，只在**条目变化时**重建，没有任何定时器
3. **App** `SearchWindow`：独立可激活小窗口（浮层是 `WS_EX_NOACTIVATE`，**收不到键盘**，
   重命名当初也是靠单开窗口解决的）；输入即过滤、回车/双击打开、Esc 关闭
4. 入口：盒子标题栏 🔍 按钮 + 盒子右键菜单「搜索条目…」；诊断面板与 `--dump-state` 增加索引状态
5. **顺带修掉一个老隐患**：`MouseClicker.DragAsync` 改用 `SendInput` 的**绝对移动**（原来用 `SetCursorPos`）

### 验证与证据

| 项 | 结果 |
|---|---|
| 搜索自动化验收 | **PASS**，10 步全过，报告见 `artifacts/search-report.md` |
| 500 条规模查询耗时 | PASS：20 次查询**最慢 4.78 ms**（服务记录单次 0.04 ms），验收标准是 < 100ms |
| 输入即时过滤 | PASS：走窗口 TextChanged 路径，「report-1」命中 20 条且首条为前缀命中；改词结果立刻变；无匹配显示 0 条；清空恢复 500 条 |
| 溢出后重建 | PASS：向真实映射目录狂写 **4000 个文件**（进程未崩溃、索引与目录自洽）；真实溢出没法稳定复现，因此**直接驱动溢出后走的那条强制重扫路径**，证明它能补回"已经丢掉的事件"（强制重扫后「晚到的文件.txt」出现，索引 4 → 5 次重建） |
| 空闲不轮询 | PASS：空闲 1 秒内索引重建次数不增长 |
| 单元测试 | **82/82**（新增 10 个索引用例 + 1 个强制重扫用例） |
| 全部验收回归 | 12 条命令全部 exit **0** |
| 设计原则守卫 | 通过 |

### 踩坑

- **`SetCursorPos` 不适合做拖动注入**：它产生的移动事件可能被合并甚至不到达窗口，
  于是交互验收**时灵时不灵**——同一组坐标连续跑三次，缩放步骤两失败一成功。
  改成 `SendInput` + `MOUSEEVENTF_ABSOLUTE|VIRTUALDESK` 后连续 4 次全绿。
  这其实是 M0 就记过的坑（"SetCursorPos 不产生经过钩子链的移动事件"），这次是它在拖动场景下的变体。
  抓取点也从贴角 6 像素改为缩进 10 像素：圆角 + 手柄自带圆角让最角落的像素在逐像素 alpha 下是透明的。
- 强制重扫后"索引重建次数没有增长"一开始判成失败——其实是**对的**：
  内容没变就不重建（这正是设计要的"没有多余重扫"）。断言要落在"内容变了 → 重扫补回来 → 索引重建"。

### 未完成（诚实说明）

- 搜索窗口是独立窗口，不是"浮层内联输入框"：这是 `WS_EX_NOACTIVATE` 的直接后果，
  换成内联输入就得让浮层抢焦点，那是拿 P2 的立身之本去换 UI 形态，不值得
- 只搜当前盒子的条目（含映射目录的内容），不跨盒子搜索；跨盒子搜索留给后续

### 下一步

issue #14：自动归类规则 DSL。

## 2026-09-19 · 会话 15：M2 文件夹映射（issue #15）

**目标**：把磁盘某个文件夹的内容映射成盒子条目（同类产品的「释放 C 盘」卖点），**实体一个都不搬**

### 完成的工作

1. **Core**
   - `FolderMap.Scan`：顶层内容 → 条目（目录在前、文件在后、按**当前区域性**排序，
     与资源管理器的中文拼音序一致；默认最多 500 条防止大目录把界面拖垮）
   - `FolderMap.Unavailable`：目标不可用时返回**一条醒目提示条目**，而不是静默给个空盒子
   - `MappedFolderWatcher`：`InternalBufferSize` 调到 64KB、**合并抖动**（300ms）、
     `Error`（缓冲区溢出/目录被拔）时整体重扫、任何失败都降级为"不可用"而不抛
2. **App**
   - `MappedFolderService`：按布局维护"一个映射盒子一个监视器"，目录一变就重扫 →
     只改布局里的 `Items` 引用 → 推给浮层；**内容没变就什么都不做**；
     FileSystemWatcher 的回调切回 UI 线程
   - `OverlayWindow.ApplyBoxUpdate`：新增"模型 → 视图"的推送方向（之前只有"视图 → 模型"）
   - `BoxView`：盒子右键菜单加「映射文件夹…」「解除映射」，映射时标题显示 `⤷` 标记；
     选目录用 WinForms `FolderBrowserDialog`，并先弹一次"不会移动/复制任何文件"的确认
   - `--selftest-map` 自动化验收；诊断面板与 `--dump-state` 增加映射监听状态

### 验证与证据

| 项 | 结果 |
|---|---|
| 映射自动化验收 | **PASS**，11 步全过，报告见 `artifacts/map-report.md` |
| 映射 = 目录内容 | PASS：3 条（子目录 / 甲.txt / 乙.txt），全部 `ItemKind.Mapped`，目录排在前面 |
| **实时反映增删** | PASS：目录里新建文件 → 盒子 3→4 条；删除文件 → 4→3 条（监视器推送，重扫 2 次） |
| **原目录不变（P4）** | PASS：用户原有条目的路径 / 类型 / 时间戳 / 大小逐项一致，撤销映射后仍一致 |
| 空闲不轮询 | PASS：空闲 1 秒内重扫次数不增长（事件驱动，无定时扫描） |
| 目标不可用 | PASS：映射不存在的目录返回失败并给出原因；扫描这类目录会得到「⚠ 映射目标不可用」条目 |
| 监视器释放 | PASS：解除映射后监视器 0 个，不留后台监听 |
| 单元测试 | **71/71**（新增 8 个映射用例，含真实临时目录的监视器通知） |
| 全部验收回归 | 11 条命令全部 exit **0** |
| 设计原则守卫 | 通过 |

### 踩坑

- **中文排序不能用 Ordinal**：`string.CompareOrdinal` 会把「甲」排到「乙」后面（按码位），
  用户看着就是乱的。改用 `CurrentCultureIgnoreCase` 与资源管理器一致。
  连带的教训是：单元测试里断言中文顺序会把机器的语言设置带进来，**顺序断言用 ASCII 名字**。
- 验收的指纹比对一开始把"验收自己新增/删除的文件"也算进去了，于是必然不一致。
  改成只比对**用户原有的、我们没动过的**条目。

### 未完成（诚实说明）

- 映射只取目录**顶层**（不递归），递归会把盒子和内存都撑爆；需要的话留给后续做"展开子目录"
- 缓冲区溢出（`Error` 事件）的重扫路径与正常变化走**同一条 Rescan**，但验收里没法真的把 64KB 缓冲撑爆
  （要生成上万次事件），因此"溢出重建 0 次"如实记录，溢出路径靠代码审查 + 同一条重建链路保证

### 下一步

issue #13：盒子内即时搜索（复用这里的监视器与重建链路）。

## 2026-09-19 · 会话 14：M2 起步——布局快照备份与还原（issue #16）

**目标**：桌面布局被意外打乱后能一键恢复（同类产品的已知缺陷就是"布局会乱"）

### 完成的工作

1. **Core**
   - `LayoutSerialization`：把布局文件与快照的序列化/版本校验抽成**同一套**——
     否则将来做 schema 迁移时会出现"布局能升级、快照升不了"的夹生状态
   - `SnapshotStore`：创建（毫秒级文件名 + 同毫秒防撞名）、按时间倒序列出、按保留份数清理、
     读取失败给出明确诊断；坏快照只影响它自己
   - `SnapshotDiff`：还原前告诉用户"会发生什么"（快照/当前显示器数量、哪些显示器不在了、
     多少个盒子会回退到兜底屏）
   - `LayoutDocument` 新增 `SnapshotKeep`（带默认值的追加字段，老文件照读，无需升版本）
2. **App**
   - `LayoutService`：暴露 `Document`、`CreateSnapshot`、`Apply`（整体替换 + 立即落盘）
   - `SnapshotsWindow`：按时间列出、新建、还原（**还原前自动存一份「还原前」**，让还原本身可回退）、
     保留份数可配置、打开快照目录
   - 托盘菜单新增「布局快照…」
   - `--selftest-snapshot` 自动化验收

### 验证与证据

| 项 | 结果 |
|---|---|
| 快照自动化验收 | **PASS**，7 步全过，报告见 `artifacts/snapshot-report.md` |
| 新建 + 列表 | PASS：写入快照目录，窗口列表按时间倒序列出且**就是绑定到界面的那份数据** |
| 还原一致性 | PASS：打乱（改名 + 移动 + 加条目）后还原，**盒子标识/名称/位置/锁定折叠/条目路径逐项与快照一致** |
| 还原可回退 | PASS：自动生成「还原前」快照 |
| 坏快照 / 缺失文件 | PASS：分别给出 `JsonException` 与「快照文件不存在」，不静默失败 |
| 单元测试 | **63/63**（新增 10 个快照用例） |
| 全部验收回归 | 10 条命令全部 exit **0** |
| 设计原则守卫 | 通过 |

### 踩坑

1. **同毫秒撞名会静默覆盖**：文件名精确到毫秒也挡不住连续创建（验收里就发生了），
   后一份直接覆盖前一份——等于悄悄弄丢一个还原点。已加序号防撞。
2. **列表顺序不能只靠 `SavedAt`**：它是秒精度的，同一秒内建的几份排序不稳定。
   改为以**文件名里的毫秒时间戳**为准。
3. **验收必须先归一化被测对象的初始状态**：这次踩了个大坑——上一次验收进程被强杀（开发中很常见），
   磁盘上留下一个**折叠**的盒子；折叠会让缩放手柄消失，于是后续每一次交互验收都莫名其妙地失败。
   修法：验收开始先把盒子归一化为「展开 / 未锁定 / 尺寸不小于 320×260」，结束再还原。
   顺带给交互验收加了**每步的命中探测**（把占用该点的窗口类名/标题写进报告），
   以后遇到假失败一眼就能看到"这个点被谁占了"。

### 未完成（诚实说明）

- 快照目前只有"手动创建"；**自动定期快照**（比如每天首次启动）留到 M3 与崩溃日志一起做
- 分辨率变化后的"自动重排"复用的是既有的 `MonitorMatcher` 回退链，
  还原时会用 `SnapshotDiff` 把差异说清楚，但没有做"按新分辨率重新布局"的智能重排

### 下一步

issue #15：文件夹映射（FileSystemWatcher 增量同步）。

## 2026-09-19 · 会话 13：M1 收尾——#10 的验收补齐与里程碑结论

**目标**：#9 落定后，M1 只剩 #10 还开着。把它的验收逐条对清楚，给 M1 一个诚实的收尾

### 完成的工作

给 `LayoutStore` 补两个直接对应 #10 第一条验收的用例：

1. **反复覆盖保存后文件始终可解析**：连着存 5 轮、每轮存完立刻读回，读到的都是当轮内容，
   且始终不留 `.tmp`——这正是「先写临时文件再 `File.Replace`」要保证的性质；
2. **写入中途被杀留下半个临时文件，不影响主文件**：手工造一个截断的 `.tmp`（模拟强杀现场），
   主文件照样读得出来、残留的临时文件也不会把下一次保存带坏。

### #10 三条验收标准的逐条结论

| 验收标准 | 结论 | 证据 |
|---|---|---|
| 临时文件 + `File.Replace`，强杀后 `layout.json` 仍可解析 | **达标** | 会话 6 的 8 个持久化用例 + 本次新增 2 个用例（53/53） |
| SchemaVersion 迁移函数有单元测试覆盖 | **对象尚不存在** | 当前只有 v1，没有迁移函数可测。写一个"没有迁移对象的迁移测试"是自欺，等 v2 出现时连迁移链一起补（会话 6 已记录同一判断） |
| 拔掉副屏再加回，盒子回到原显示器 | **单测达标，真实设备待人工** | `MonitorMatcher` 6 个用例（Id 精确 → 分辨率相同 → 兜底）；真实拔插与 #5 的人工验证是同一件事 |

## 2026-09-19 · 会话 1：立项、技术方案与开发流程搭建

**参与者**：1EM0NS（人）、Trae（AI 助手）

**目标**：确定桌面整理助手的技术方案，并建立一个能长期做版本迭代的仓库与工作流

### 调研结论

- 腾讯桌面整理「开整理后动态壁纸点不动」的根因**不是资源占用，而是输入抢占**：它铺透明分层窗口并拦截鼠标消息，与 Wallpaper Engine 依赖的全局鼠标钩子（`WH_MOUSE_LL`）争抢输入。官方只能提供"兼容第三方壁纸"开关，并承认交互型壁纸不支持。

### 踩过的坑（都是可复现的环境问题）

1. **全局 git 代理失效**：`~/.gitconfig` 里 `http.proxy = 127.0.0.1:7890` 指向未监听的端口，而实际代理端口是动态的（本次为 38144）。已在**本仓库** `.git/config` 把 `http/https.proxy` 置空以覆盖全局，不影响其他仓库。
2. **PowerShell 5.1 会丢弃空字符串参数**：`git config --local http.proxy ""` 实际上没有写入，而 `git config --get` 返回空会**造成"已生效"的假象**。正确做法是直接编辑 `.git/config`，或用 `git -c key=value` 形式。
3. **PowerShell 参数模式不做成员访问**：`gh api -f title=$m.Title` 会把字面量 `System.Collections.Hashtable.Title` 当标题提交（曾产生一个垃圾里程碑，已删除）；描述里的 ASCII 双引号还会破坏原生参数解析。
   → **结论：给 `gh` 传中文内容一律用 `--body-file` 传文件。**
4. **PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 ANSI 解析**，中文报语法错误。`guard.ps1` 已加 BOM。
5. GitHub 不允许 approve 自己的 PR，所以分支保护的强制审批人数必须为 **0**，否则单人项目会把自己彻底锁死。
