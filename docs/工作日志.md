## 2026-09-19 · 会话 4：M0 收尾——验收工具落地、三项结论闭环

**目标**：补齐 issue #4 的验收工具，把 M0 的四个 issue 全部闭环

### 人工验证结果（由项目所有者执行并确认）

- 浮层可见；鼠标在桌面空白处显示命中 `SysListView32`/`Progman`（不是浮层），在盒子内显示命中浮层 —— **通过**
- `Win+D` 后浮层恢复显示 —— **通过**
- Wallpaper Engine 互动壁纸按钮在浮层开启前后点击行为一致 —— **通过**

### 完成的工作

1. `tools/ZOrderProbe`：窗口链快照 + 置底断言（`--assert-behind --exe <进程> --title <标题>`），支持 `--json` 供前后 diff
2. `tools/HookProbe`：鼠标钩子链探针，支持 `--out` 采集基线与 `--baseline` 对比判定
3. `ADR-0003`：允许验收工具注册观测用钩子（仅观测、无条件放行），源码中显式标注豁免
4. `DesktopProbe.DesktopLayerChain()`：定位「持有 SHELLDLL_DefView 的顶层窗口 → DefView → SysListView32」
5. `MouseClicker.Nudge()`：用 SendInput 产生**真实**移动事件
6. 证据文档扩充并更名为 `docs/m0-evidence.md`（会话 3 里写的 `docs/m0-hittest-evidence.md` 已被此文件取代）

### 验证与证据

| 项 | 结果 |
|---|---|
| 置底断言 | **PASS**：浮层位于第 17/21 位，其下方仅 3 个窗口且全部是桌面层（WorkerW×2 + Progman） |
| 钩子链基线对比 | **PASS**：基线按下 6/10 → 运行中 8/10，抬起均为 10/10，运行态不差于基线 |
| 单元测试 | 7/7 |
| 设计原则守卫 | 通过（HookProbe 的钩子为 ADR-0003 显式豁免） |
| 编译 | 7 个项目 0 警告 0 错误 |

完整原始数据见 `docs/m0-evidence.md`。

### 踩坑（这一轮全是"测试本身不可靠"，比代码 bug 更值得记）

1. **ZOrderProbe 的判据反了**：原来检查「我们上方有没有应用窗口」，但置底的含义是「我们**下方**不该压着应用窗口」。第一版还匹配到了同进程的诊断面板窗口（它本来就在顶层），给出一个**假 PASS**。
2. **只按 pid 匹配会挑错窗口**：一个进程有多个窗口，必须用 `--title` 精确过滤。
3. **大量窗口停在 `(-25600,-25600)`**：Windows 把隐藏窗口挪到屏幕外，但它们 `IsWindowVisible` 依然为真，会被误判成"被我们遮挡"。断言必须按矩形相交过滤。
4. **HookProbe 漏数双击**：同一位置快速连点，系统把第二次按下变成 `WM_LBUTTONDBLCLK`，不计它就会误判成「有人吞消息」。
5. **`SetCursorPos` 不产生经过钩子链的移动事件**，用它来判断"钩子是否活着"完全无效，必须用 SendInput 的相对移动。
6. **绝对计数在共享环境里没有意义**：本机**基线状态**下就丢按下事件（6/10）——上游是 Wallpaper Engine 在吞点击（窗口快照里能看到它的 `WPEUI`）。判据只能是「不差于基线」，这也是最初差点误判 Cubby 的根源。

### 结论

**M0 门禁达成**：issue #1–#4 全部闭环，打 `0.1.0`。

### 下一步

进入 M1：布局模型与持久化 → 多显示器浮层 → 盒子交互 → 拖放 → 托盘 → 图标吸附。

## 2026-09-19 · 会话 3：M0 spike 落地，命中测试双向验证通过

**参与者**：1EM0NS（人）、Trae（AI 助手）

**目标**：回答 issue #1 —— 「盒子区域可点、其余区域点击穿透」是否在真机上成立

### 完成的工作

1. **工程骨架**：`Cubby.sln` + Core / Shell / App / Tests 四层，进程固定 x64，PMv2 每显示器 DPI 感知（若被编译器和 CI 接受，M1 起 CI 开始真正构建）
2. **Core（纯逻辑、可单测）**：DIP↔物理像素换算、命中区域计算，7 个单元测试覆盖
3. **Shell**：`OverlayHost`（分层窗口、两种命中模式、事件驱动置底、区域构建）、`WindowPlacement`、`DesktopProbe`（WindowFromPoint / Z 序快照）、`MouseClicker`（SendInput 注入）
4. **App**：带 `selftest` 参数时自动跑命中测试并产出报告；无参启动是交互式诊断面板（实时显示「光标所在位置会被谁收到」）

### 验证与证据

环境：Microsoft Windows 10.0.19045 / .NET 8.0.31 / x64 / 2560×1440 @ 125% 缩放

| 项 | 结果 |
|---|---|
| 自测退出码 | **0（PASS）**，两种命中模式都通过 |
| 逐像素 alpha | 盒子内 2 点：命中「被测浮层」且浮层收到注入点击；盒子外 3 点：命中「受控背景层」且背景层收到点击 |
| 窗口区域 | 同上，5 个采样点全部 PASS |
| 单元测试 | **7/7 通过** |
| 设计原则守卫 | **通过（exit 0）** |
| 编译 | Release 0 警告 0 错误 |

原始报告与完整数据：`docs/m0-hittest-evidence.md`

**issue #1 的结论**：WPF `AllowsTransparency` 窗口在 alpha=0 处确实放行点击 → **方案 A 逐像素 alpha 成立，不需要降级到 `SetWindowRgn`**。`技术方案.md` 2.2 的决策已同步更新。

### 踩坑（后人请勿重犯）

1. **Z 序方向搞反**：`SetWindowPos(hwnd, insertAfter, ...)` 里的 `insertAfter` 是「排在它前面（即更上层）」的窗口，传入背景层会把背景层压到浮层**之上**。第一版因此 5 个采样点全部命中背景层。改用「背景层先置顶、浮层后置顶」的明确顺序后一次通过。
2. **第一版自测把点击注入到了第三方窗口**：当时桌面上有个最大化窗口盖住全屏，采样点全打在它上面，等于在乱点用户程序。改成「被测浮层 + 自建受控背景层」对打后，既不依赖用户桌面状态，也不可能误点别人的程序。
3. WPF 项目的隐式 using **不含 `System.IO`**，用 `Path` / `File` 必须显式 `using System.IO;`。
4. `.csproj` 的 XML 注释里**不能出现连续两个短横线**（写了 `--selftest` 会导致项目直接加载失败）。
5. 本机原本只有 .NET 运行时、没有 SDK，已装 .NET SDK 8.0.425。

### 遗留问题

- **issue #2 置底**：已实现（`HWND_BOTTOM` + `SetWinEventHook` 事件驱动，无轮询）但**尚未验收**，需在真实桌面上人工确认「可见 + 不遮挡应用窗口 + Win+D 后恢复」
- **issue #3 WE 互动壁纸基线**：无法自动化，需人工；诊断面板会实时显示光标处的命中窗口作为客观依据
- **issue #4 ZOrderProbe / HookProbe 独立工具**：目前只有自测内建的探针，独立可复用工具未建

### 下一步

用诊断面板完成事先列好的人工步骤（置底与 WE 共存），四项都过了再打 `0.1.0`。

### 新增环境坑

## 2026-09-19 · 会话 1：立项、技术方案与开发流程搭建

**参与者**：1EM0NS（人）、Trae（AI 助手）

**目标**：确定桌面整理助手的技术方案，并建立一个能长期做版本迭代的仓库与工作流

### 调研结论

- 腾讯桌面整理「开整理后动态壁纸点不动」的根因**不是资源占用，而是输入抢占**：它铺透明分层窗口并拦截鼠标消息，与 Wallpaper Engine 依赖的全局鼠标钩子（`WH_MOUSE_LL`）争抢输入。官方只能提供"兼容第三方壁纸"开关，并承认交互型壁纸不支持。
- 可借鉴的开源方案：DeskBox（文件不移动、只做映射浮层）、Lively Wallpaper（WorkerW + `SetParent` 塞进壁纸层）、DesktopOK（`LVM_*` 读写图标位置）、Rainmeter（桌面小组件 Z 序）、Seelen UI。
- 技术结论：`WM_NCHITTEST → HTTRANSPARENT` **跨进程无效**（消息被丢弃而非转发），不能用来实现穿透。

### 决策

- 技术栈 .NET 8 + WPF，进程固定 x64（与 Explorer 同位宽才能做 `LVM_*` 通信）
- 四条硬约束 P1–P4（见 `技术方案.md` 1.2），并落成 CI 门禁
- 仓库名 **Cubby**（Public），trunk-based + PR，SemVer 与里程碑绑定
- 「双击空白桌面隐藏图标」默认不做（与 P1 冲突），改为托盘菜单 / 热键 / 盒子按钮
- 不把窗口 `SetParent` 到 WorkerW（ADR-0001）；不注册全局鼠标钩子（ADR-0002）

### 完成的工作

1. `技术方案.md`：竞品痛点、桌面图层模型、P1–P4、验收标准 A1–A8、里程碑门禁、第 13 章开发流程
2. 仓库初始化，首个提交 `1141b0e`（9 个文件 740 行）

### 踩过的坑（都是可复现的环境问题）

1. **全局 git 代理失效**：`~/.gitconfig` 里 `http.proxy = 127.0.0.1:7890` 指向未监听的端口，而实际代理端口是动态的（本次为 38144）。已在**本仓库** `.git/config` 把 `http/https.proxy` 置空以覆盖全局，不影响其他仓库。
2. **PowerShell 5.1 会丢弃空字符串参数**：`git config --local http.proxy ""` 实际上没有写入，而 `git config --get` 返回空会**造成"已生效"的假象**。正确做法是直接编辑 `.git/config`，或用 `git -c key=value` 形式。
3. **PowerShell 参数模式不做成员访问**：`gh api -f title=$m.Title` 会把字面量 `System.Collections.Hashtable.Title` 当标题提交（曾产生一个垃圾里程碑，已删除）；描述里的 ASCII 双引号还会破坏原生参数解析。
   → **结论：给 `gh` 传中文内容一律用 `--body-file` 传文件。**
4. **PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 ANSI 解析**，中文报语法错误。`guard.ps1` 已加 BOM。
5. GitHub 不允许 approve 自己的 PR，所以分支保护的强制审批人数必须为 **0**，否则单人项目会把自己彻底锁死。
